# 試聴用の部分変換（--force）

`--force`は、変換処理が未完成でも、扱える部分のMML・試聴用ファイルを
生成するための明示的な損失許容です。既定では無効です。
`vgm2mml.py`と`scripts/export_mdx.py`で指定できます。

OPNA→OPM→MDXでは未対応HWの省略を行います。ネイティブOPM／対応PCM、
OPM＋SegaPCM経路でもPDX容量の省略に使えます。
単独のPSG→OPM経路にもforceを適用でき、PSGとSSGは同じ共通投影処理で
未対応のノイズ／HWエンベロープ区間を省略します。
入力破損、未解決のソース証拠、対応外のソース経路・ストリーム、
不正クロック、外部ツール不足・コンパイラ制限はこの段階では回避しません。

```bash
python scripts/export_mdx.py input.vgm \
  --outdir outputs/listen/forced --no-vgm \
  --compiler mmlx --pcm-policy best-effort --force
```

## 未対応HWの扱い

| 対象 | force時の出力 |
|---|---|
| 未分類のOPNAレジスタ効果 | 元の書き込みを記録し、ターゲットへの効果を省略 |
| PSG／SSGノイズ・ハードウェアエンベロープ | 未対応区間全体を無音化。対応するトーン区間は出力 |
| CH3特殊周波数／CSM | CH3だけを該当区間で出力ゲート。他のチャンネルは継続 |
| FMオペレータのSSG-EG | 有効な間、そのチャンネルを出力ゲート |
| OPMチャンネル不足で割り当てられないSSGパート | 既存のFM優先割当を維持し、省略したパート名と理由を表示 |
| リズム・IRQなど従来の未投影制御 | 省略一覧にも表示 |
| LFOなど既存の近似 | 「書き込み省略」と区別して近似として表示 |
| 対応できないDELTA制御（既知のrepeat・記録モード等） | PCM部全体を省略し、FM／SSGを継続 |

FMの出力ゲート中も通常のキー・音色・通常音程の投影を継続します。
復帰時に合成Key-Onを追加せず、保持した通常のキー状態で出力を戻します。
CSMの自動キーや元のEG位相は再構築しません。これは明示的な試聴用近似です。

DELTAの保持中の音量・パン・速度変更は対応経路を継続します。
元データの欠落、未知の診断、壊れた状態やソース証拠を無視して
PCMを生成することはありません。

「未割当のオペレータ欄」は書き込みが無いという意味ではありません。
通常のFMオペレータのアドレス配置で、チャンネル欄が0～2なのに3となる
番号（例: `0x80/81/82`に続く`0x83`）です。
VGMにはその番号への書き込みも存在できます。これも原本に保持し、
force時のターゲット投影から省略します。他の未分類レジスタも
一律に安全とは判断せず、未対応効果を省いた事実を一覧に残します。
配置の実装参照: [ymfm](https://github.com/aaronsgiles/ymfm/blob/main/src/ymfm_opn.h)。
実機上のすべての未公開効果を検証したという意味ではありません。

## PCM容量

元のPCM IRを変更せず、ターゲットへの音色採用を最初の発音順に行います。

- 1バンク96音色まで。満杯後は新しい音色を省略し、採用済み音色の再利用は継続。
- 検証済みの1音色65,535 encoded bytesを超える音色は、途中で切らず全体を省略。
  その音色はスロットを消費しないため、後続の収まる音色は採用可能。
- 省略した音色を参照する発音は休符として扱い、曲の終端・ループ位置を保持。
- 全PCMを省略した場合、残るFMのMMLを生成し、空PDXを要求しない。

65,535 bytesは現在の検証済み投影範囲であり、PDX形式そのものの上限ではありません。
MUCOMの256 KiBバンク上限とも異なり、ここでは総容量256 KiBの制限を追加しません。
元IRの解析や最終クロック合わせのための生成処理は継続するので、
forceが必ず変換時間を短縮するわけではありません。

容量省略は正規化による短音省略とは別です。`--force`が許可するのは
明記した容量省略であり、他の未検証・意味損失をまとめて許可しません。
PCM再圧縮の既知損失には引き続き`--pcm-policy best-effort`が必要です。

## 一覧と診断

変換後のコンソールとTXTにはポート・レジスタ番号・対象ビット・対処・理由を
一覧表示します。省略対象のパート名（PSG1、SSG3、FM3など）も表示します。`write`は書き込み、`interval`は区間、`part`は部全体の
判定です。件数は同じ意味の書き込み数ではなく、ループ展開後の判断件数です。
元Segmentに存在するイベントID・ループ反復・原時刻も保存します。
その情報を持たないPSG Segmentでは値を作らず、空欄と元の行・時刻を使います。

区間を無音にする原因は区間開始の書き込みより前に設定されることがあります。
診断の`register`は対象機能、`trigger_register`は区間を区切った書き込みです。
レジスタ全体を省略する場合と、一部ビットの機能だけ省略する場合を区別します。

- `<stem>.opna_force.skipped_registers.csv/.json`: OPNAの全判断と集約一覧。
- `<stem>.psg_force.skipped_registers.csv/.json`: 単独PSG経路の省略区間と集約一覧。
  元イベントIDがSegmentに存在しない場合は空欄とし、元Segment行・時刻を記録します。
- `<stem>.opna.unmodeled.csv`: 未解釈の元書き込み証跡。
- `<stem>.opna_ssg.segments.csv`: 変更しない元のSSG Segment。
- `<stem>.opna_ssg.omissions.csv/.json`: SSG省略区間。
- `<stem>.opna_fm.omissions.csv/.json`: 未投影のレジスタ書き込み。
- `<stem>.pcm.force_capacity.csv/.json`: 音色・発音ID、容量理由、actual/limit、
  元の時刻、採用／省略の判断。
- `<stem>.opna-opm.json`と`.conversion.json`: `force_projection`。
  後者では`projection_settings`内。

試聴用exportの詳細CSV／JSONは`_diagnostics`以下、
配布用TXTは`tracks/<stem>/`に保存します。
同時発音するチャンネルの省略時間は重複し得るため、
その合計を曲の短縮時間と解釈しないでください。
生成成功は元音声との一致や実機での再生を保証しません。

## コンパイラ

このチェックポイントではコンパイラ制限への自動回避を見送っています。
`--force`でもコンパイルが失敗すれば、成功とは表示しません。
生成済みMML・PCM IR・診断を残し、エラーを報告します。


force指定のないチャンネル割当の方針は変更しません。
OPNAの従来のFM優先・余剰SSGパート省略は引き続き割当診断にも記録します。
force指定時は、レジスタ一覧でも省略パート名をまとめて確認できます。
